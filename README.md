Реализовано в DentalClinic — Синхронизация и бэкап
Зависимости: kotlinx-serialization-json, Ktor-client (okhttp/java), Ktor-server (netty)
Desktop БД: ~/.dental-clinic/dental.db — данные теперь сохраняются между запусками
Бэкап (JSON):
- Экспорт всех данных → ~/.dental-clinic/backups/backup_<timestamp>.json
- Импорт из JSON → восстановление всех данных
- Работает на Android (в context.filesDir/backups/)
Синхронизация:
- Desktop: Ktor сервер стартует авто (порт 9876)
- Android: подключается по IP, Push/Pull через настройки
- Endpoints: GET /api/sync/ping, POST /api/sync/pull, POST /api/sync/push
Экран «Настройки» в боковом меню: Backup, Restore, Push, Pull
APK: Builds/DentalClinic-debug.apk

## Тест-кейсы для мануального тестирования (синхронизация и бэкап)

### TC-SYNC-001: Создание резервной копии (экспорт)
- **Предусловие**: В БД есть пациенты, приёмы, зубы, диагнозы, планы лечения, визиты, счета, позиции прайс-листа (сиды)
- **Шаги**: 1) Открыть экран «Настройки» в боковом меню  2) Нажать «Создать резервную копию (экспорт)»
- **Ожидаемый результат**: В `~/.dental-clinic/backups/` появился `backup_<timestamp>.json` и `backup_latest.json`. Файл содержит валидный JSON со всеми 12 разделами данных.

### TC-SYNC-002: Восстановление из резервной копии (импорт)
- **Предусловие**: Существует `backup_latest.json` (создан через TC-SYNC-001)
- **Шаги**: 1) Изменить/удалить несколько записей в приложении  2) Открыть «Настройки» → «Восстановить из резервной копии (импорт)»  3) Перезайти в разделы с данными
- **Ожидаемый результат**: Все данные вернулись к состоянию на момент бэкапа. Изменения, сделанные после бэкапа, пропали.

### TC-SYNC-003: Проверка целостности после импорта
- **Предусловие**: Выполнен TC-SYNC-002
- **Шаги**: 1) Проверить список пациентов — количество, ФИО, даты рождения  2) Открыть карту любого пациента — проверить одонтограмму, диагнозы, планы лечения, визиты, счета  3) Проверить прайс-лист
- **Ожидаемый результат**: Все сущности отображаются корректно. Связанные данные (визиты → позиции, счета → позиции счетов) консистентны.

### TC-SYNC-004: Экспорт с пустой БД
- **Предусловие**: Приложение только что установлено, сиды не загрузились (или вручную очищены)
- **Шаги**: 1) Открыть «Настройки» → «Создать резервную копию»  2) Открыть полученный JSON-файл
- **Ожидаемый результат**: Файл создан. JSON содержит все 12 ключей, каждый — пустой массив `[]`.

### TC-SYNC-005: Импорт повреждённого JSON
- **Предусловие**: В `backup_latest.json` подменено содержимое на некорректный текст (например, `{broken json`)
- **Шаги**: 1) Открыть «Настройки» → «Восстановить из резервной копии»
- **Ожидаемый результат**: Приложение не падает. Появляется сообщение об ошибке («Ошибка импорта» или подобное). Текущие данные в БД не изменяются.

### TC-SYNC-006: Выбор облачной папки (Desktop)
- **Предусловие**: Запущен Desktop-клиент. В файловой системе есть папка (например, Google Drive / Yandex.Disk / произвольная)
- **Шаги**: 1) Открыть «Настройки» → секция «Синхронизация с облаком»  2) Нажать «Выбрать файл синхронизации»  3) В диалоге выбрать целевую папку  4) Нажать «Отправить в облако»
- **Ожидаемый результат**: Статус изменился на путь к выбранной папке. Кнопки «Отправить в облако» и «Загрузить из облака» активны. В целевой папке появился файл `sync.json`.

### TC-SYNC-007: Выбор файла синхронизации (Android)
- **Предусловие**: Запущен Android-клиент
- **Шаги**: 1) Открыть «Настройки» → «Выбрать файл синхронизации»  2) В SAF-диалоге выбрать папку (например, облачное хранилище) и создать/выбрать файл `.json`  3) Нажать «Отправить в облако»
- **Ожидаемый результат**: URI сохранился в SharedPreferences. Статус отображает имя файла. Данные записались в выбранный файл.

### TC-SYNC-008: CloudSync Push (отправка в облако)
- **Предусловие**: CloudSyncStorage настроен (TC-SYNC-006 или TC-SYNC-007). В БД есть данные.
- **Шаги**: 1) Внести изменения в БД (добавить/изменить пациента)  2) Открыть «Настройки» → «Отправить в облако»
- **Ожидаемый результат**: Файл `sync.json` обновился и содержит актуальные данные (с учетом последних изменений).

### TC-SYNC-009: CloudSync Pull (загрузка из облака)
- **Предусловие**: Выполнен TC-SYNC-008. Текущие данные в БД отличаются от данных в облаке.
- **Шаги**: 1) Открыть «Настройки» → «Загрузить из облака»  2) Перезайти в разделы с данными
- **Ожидаемый результат**: Данные в БД заменились на данные из `sync.json`. Локальные изменения, не отправленные в облако, потеряны.

### TC-SYNC-010: CloudSync с пустой БД
- **Предусловие**: CloudSyncStorage настроен. БД пуста.
- **Шаги**: 1) Нажать «Отправить в облако»  2) Нажать «Загрузить из облака»
- **Ожидаемый результат**: Push — в `sync.json` записались пустые массивы. Pull — БД осталась пустой, ошибок нет.

### TC-SYNC-011: Кроссплатформенный перенос Desktop → Android
- **Предусловие**: На Desktop создан `backup_latest.json` (TC-SYNC-001)
- **Шаги**: 1) Скопировать `backup_latest.json` с Desktop на Android-устройство  2) На Android заменить файл бэкапа в `context.filesDir/backups/backup_latest.json`  3) Открыть приложение на Android → «Настройки» → «Восстановить из резервной копии»
- **Ожидаемый результат**: Все данные с Desktop успешно импортированы на Android. Одонтограмма, визиты, счета отображаются корректно.

### TC-SYNC-012: Кроссплатформенный перенос Android → Desktop
- **Предусловие**: На Android создан бэкап (TC-SYNC-001)
- **Шаги**: 1) Скопировать `backup_latest.json` с Android на Desktop  2) На Desktop заменить файл в `~/.dental-clinic/backups/backup_latest.json`  3) Открыть приложение на Desktop → «Настройки» → «Восстановить из резервной копии»
- **Ожидаемый результат**: Все данные с Android успешно импортированы на Desktop. Все разделы отображаются корректно.
